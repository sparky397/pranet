# 訂正の提案のしかた

pranet の間違いを見つけた人が、直すために読む文書。書いた日：2026-10-09。
仕組みは設計図 15.3「利用者みんなで間違いを直す」のとおり。

## 1. 考え方

- **提案は誰でも。公開には出典が必要。** 出典（URL）の無い訂正は載せられない（設計図の原則 1）。
- 確認する人は「専門家として正しいか」ではなく「出典にそう書いてあるか」だけを見る。
- 訂正は消さない。取り消すときは「取り消した」という記録を足す（設計図 16 章）。
- 元の間違いが Wikipedia・Wikidata・World Flora Online にある場合は、そちらで直すのがいちばん効く（世界中が直る）。pranet は次の取り直しで追いつく。

## 2. 送り方（3 つのどれでも）

| 方法 | 向いている人 |
|---|---|
| アプリの種のページ → 「✎ 間違いを報告」 | GitHub のアカウントがある人。雛形が埋まった Issue が開く |
| アプリの種のページ → 「✎ 報告文をコピー」 → 掲示板やメールに貼る | アカウントが無い人。貼られた文を確認役が訂正ファイルにする |
| 自分で訂正ファイルを書いて Pull Request | git に慣れた人 |

雛形の項目（アプリが出すもの）：

```
種: Oryza sativa (wfo-0000882438)
https://sparky397.github.io/pranet/app/#/species/wfo-0000882438
項目（名前 / 説明 / 食用 / 用途 / 分布 など）:
間違い:
正しい内容:
出典（URL、必須）:
出典のライセンス:
提案者の名前（表示してよい場合。空欄なら匿名）:
```

## 3. 訂正ファイルの形

場所：`data/overrides/<WFO番号>.json`（1 種 1 ファイル。種の番号はアプリの種のページの出典欄にある）。

```json
{
  "id": "wfo-0000882438",
  "overrides": [
    {
      "field": "names.ja",
      "value": ["イネ", "稲"],
      "source": "日本語版 Wikipedia「イネ」",
      "source_url": "https://ja.wikipedia.org/wiki/イネ",
      "license": "CC BY-SA 4.0",
      "proposer": "匿名",
      "date": "2026-10-10",
      "note": "常用漢字の表記も検索できるように",
      "status": "accepted"
    }
  ]
}
```

| 項目 | 内容 |
|---|---|
| `field` | 直す項目。下の一覧のどれか |
| `value` | 新しい値。項目ごとに形が決まっている（下の一覧） |
| `source` / `source_url` | 出典の名前と URL。URL は必須 |
| `license` | 出典のライセンス。使えるのは CC0 1.0、CC BY（2.0〜4.0）、CC BY-SA（2.0〜4.0）、Public domain |
| `proposer` | 表示してよい名前。空欄か「匿名」でもよい |
| `date` | 日付（YYYY-MM-DD） |
| `note` | 任意。なぜ直すかの短い説明 |
| `status` | `accepted`（反映する）か `retracted`（取り消した。記録として残す） |

同じ種に複数の訂正があれば配列に順に足す。同じ項目を 2 回直したら、後のものが勝つ。

### 直せる項目

| `field` | `value` の形 | 意味 |
|---|---|---|
| `names.<言語>`（例 `names.ja`） | 文字列の配列 | 表示する一般名。先頭が主表示 |
| `description.<言語>` | `{"text": "…"}` | 説明文を差し替える。出典とライセンスはこの訂正のものになる |
| `edible.is_food` | `true` / `false` | 食用の記録 |
| `edible.use_codes` | 配列（HF AF ME MA EU GS PO SU FU IF） | 用途の印 |
| `distribution.native` / `distribution.introduced` | 地区コード（TDWG レベル 3）の配列 | 分布 |
| `hidden` | `true` | 種を公開から外す（データは残る） |

写真の訂正はまだ受け付けていない（画像ファイルの扱いが別に要る）。写真が間違っている場合は Issue で知らせてほしい。

## 4. 確認役がすること

1. `source_url` を開き、`value` がそこに書いてあるか見る。無ければ `status` を `retracted` にして `note` に理由を書く。
2. `python3 scripts/validate.py` を実行し「訂正の層（data/overrides）」が `[ok]` であること。
3. `python3 scripts/build_pack.py` を実行する。訂正は種のデータに重なり、種のページの出典欄に「訂正：項目 · 出典 · 提案者 · 日付」として出る。
4. commit して公開する。

元データを取り直しても `data/overrides/` は残り、必ず最後に重なる。
